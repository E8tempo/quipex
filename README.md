# Квипекс — интернет-магазин систем отопления (опт и розница)

- **Фронтенд:** Next.js 16 (App Router, React 19, Tailwind 4, shadcn/ui)
- **Бэкенд:** FastAPI (async) + SQLAlchemy 2 (async) + PostgreSQL + Alembic
- **Каталог:** импортируется с e8.ru встроенным парсером (категории, товары, цены, фото, характеристики, документы)
- **Веб-сервер:** Caddy — автоматический HTTPS (Let's Encrypt), раздача фото, проксирование API

## Запуск на сервере

Нужен сервер с Docker и Docker Compose. Если сайт будет на домене, его DNS (A-запись) должен указывать на IP сервера.

```bash
# 1. Скопировать проект на сервер, перейти в папку
cd quipex

# 2. Создать конфиг и заполнить значения с пометкой «ОБЯЗАТЕЛЬНО»
cp .env.example .env
nano .env

# 3. Запустить
docker compose up -d --build
```

Минимально в `.env` нужно поменять:

| Переменная | Что указать |
|---|---|
| `SITE_URL` | Адрес сайта, например `https://quipex.ru` |
| `SITE_ADDRESS` | Домен(ы) для HTTPS: `"quipex.ru, www.quipex.ru"` (или `:80` — без HTTPS, для проверки по IP) |
| `POSTGRES_PASSWORD` | Пароль БД |
| `SECRET_KEY` | Случайная строка: `openssl rand -hex 32` |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Логин и пароль первого администратора |

> Если сайт открывается по `http://` (например, по IP с `SITE_ADDRESS=:80`), то и `SITE_URL` должен начинаться с `http://`, иначе браузер не сохранит cookie входа в админку.

Миграции БД применяются автоматически при старте, администратор создаётся автоматически.

### Первое наполнение каталога

1. Откройте `https://ваш-домен/admin`, войдите под `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
2. Раздел **«Импорт с e8.ru»** → **«Полная синхронизация»** → «Запустить». Первый импорт ~170 товаров с фото идёт около получаса: запросы к источнику специально медленные, иначе e8.ru блокирует IP сервера. Прогресс и лог видны на странице.
3. В **«Настройках»** заполните телефон, email, адрес, реквизиты, условия опта, наценку.

Дальше синхронизация идёт автоматически раз в `PARSER_AUTO_SYNC_HOURS` часов (0 — только вручную), ночью в `PARSER_AUTO_SYNC_HOUR` по Москве. Перезапуск сервера импорт не запускает, а чаще раза в `PARSER_MIN_INTERVAL_MINUTES` минут его нельзя запустить и вручную.
Импорт можно запустить и из консоли: `docker compose exec backend python -m app.cli import`.

## Возможности

**Витрина**
- Каталог с деревом категорий, мега-меню, фасетными фильтрами по характеристикам, ценой, наличием, сортировкой
- Мгновенный поиск с подсказками (Ctrl+K), поиск по названию и артикулу
- Карточка товара: галерея с зумом и свайпом, характеристики, документы (PDF), отзывы, похожие товары
- Корзина-шторка, пересчёт цен на сервере; **оптовые цены** автоматически — от N штук одной позиции или от суммы заказа
- Оформление заказа для физ. и юр. лиц (организация, ИНН), выбор доставки и оплаты
- Избранное, сравнение товаров (с режимом «только различия»), недавно просмотренные
- Отслеживание статуса заказа по номеру и телефону
- Формы: обратный звонок, оптовый запрос, вопрос по товару, «купить в 1 клик» (с защитой от ботов)
- Тёмная тема, адаптивность под телефоны, SEO: метатеги, Open Graph, sitemap.xml, robots.txt, JSON-LD (Product, BreadcrumbList)

**Админ-панель** (`/admin`)
- Дашборд: выручка, график продаж за 30 дней, топ товаров, последние заказы
- Заказы: фильтры, поиск, смена статуса, скидка менеджера, заметки, печать, экспорт в CSV
- Заявки (звонки, опт, вопросы, предзаказы), модерация отзывов
- Товары: таблица с быстрым редактированием цены и переключателями, массовые действия (публикация, хиты, изменение цен на %, оптовые цены, перенос в категорию), полный редактор (фото с загрузкой и сортировкой, характеристики, описание, документы, SEO)
- Категории (дерево, иконки, SEO), информационные страницы (доставка, гарантия и т.д.)
- Импорт с e8.ru: полный или только цены/наличие, прогресс в реальном времени, история, остановка
- Настройки сайта (контакты, главная, опт, наценка, способы доставки/оплаты), пользователи и роли

**Синхронизация с e8.ru**
- Ручные правки не теряются: «Закрепить цены» и «Не обновлять контент» на товаре
- Наценка на цены источника и автоматический расчёт оптовых цен — в настройках
- Товары, пропавшие с источника, снимаются с публикации (с защитой от сбоев источника)

**Приложение (PWA)**
- Сайт устанавливается на телефон и компьютер как приложение: кнопка «Установить приложение» в меню и подвале (Android/Chrome — системный диалог, iPhone — подсказка «Поделиться → На экран „Домой“»)
- Быстрая повторная загрузка: статика и фото кешируются; открытые ранее страницы доступны без сети, для остальных — страница «Нет подключения»
- Цены, наличие, корзина и заказы всегда берутся из сети — устаревшие данные не показываются
- Для установки нужен HTTPS (Caddy настроит его автоматически при указании домена в `SITE_ADDRESS`)

**Уведомления** о заказах, заявках и отзывах — в Telegram и/или на email (настраивается в `.env`).

## Обслуживание

```bash
docker compose logs -f backend          # логи бэкенда
docker compose pull && docker compose up -d --build   # обновление после изменения кода
docker compose exec backend python -m app.cli create-admin email@site.ru 'новый-пароль'   # сброс пароля админа

# резервная копия БД
docker compose exec db pg_dump -U quipex quipex > backup.sql
```

Данные хранятся в Docker-томах: `pgdata` (БД), `media` (фото), `caddy_data` (сертификаты).

## Разработка

Нужны Python 3.12+, Node.js 20+ и Docker (только для базы данных).

```bash
make setup     # venv + npm install, создаст .env.dev из .env.dev.example
make dev-db    # Postgres для разработки (docker, порт 5433)
make dev-api   # миграции + бэкенд с автоперезагрузкой → http://localhost:8000/api/docs
make dev-web   # фронтенд → http://localhost:3000   (в другом терминале)
make import    # наполнить каталог с e8.ru
```

- Конфиг разработки — `.env.dev` (не попадает в git), фронтенду — `frontend/.env.local`.
  Продакшен-конфиг `.env` разработка не трогает: бэкенд читает файл из `ENV_FILE` (Makefile ставит `.env.dev`).
- Вход в админку в dev: `admin@localhost.dev` / `admin12345` (из `.env.dev`).
- Изменили модели → `make migration m="что изменилось"`, затем `make migrate`.
- `make check` — проверка типов и линтеры.

## Клиенты и партнёры

| | Покупатель | Партнёр |
|---|---|---|
| Регистрация | `/register` | `/register?partner=1` или «Стать партнёром» в кабинете |
| Доступ | сразу | после одобрения менеджером (Админка → Клиенты → Заявки) |
| Цены | розница; опт — от N шт. или от суммы корзины | цена его **типа цен** → персональная скидка от розницы → оптовая цена товара |
| Заказ | физ. или юр. лицо | всегда на организацию партнёра |

Личный кабинет (`/account`): профиль, история заказов с повтором заказа, смена пароля, заявка на партнёрство.
Партнёрские цены видны прямо в каталоге, на странице товара и в корзине.

Типы цен (Админка → Типы цен) соответствуют видам цен 1С; цены товаров по типам — в карточке товара
в админке или из обмена с 1С. Один тип отмечается «по умолчанию для партнёров».

## Сессии

- Короткий access-токен (15 мин) + refresh-токен (30 дней) в httpOnly-cookie; в БД хранится только хеш refresh-токена.
- Refresh-токен меняется при каждом обновлении (ротация). Повторное использование старого токена —
  признак кражи: вся цепочка входа отзывается.
- Выход, смена пароля и блокировка клиента/сотрудника завершают сессии сразу.
- Сессии сотрудников (админка) и клиентов сайта разделены.
- Браузер обновляет сессию сам — пользователь остаётся в системе, пока заходит хотя бы раз в 30 дней.

## Обмен с 1С (CommerceML)

Подготовлено: идентификаторы 1С у товаров, типов цен, клиентов и заказов; таблица цен по типам;
эндпоинт протокола `https://ваш-домен/api/1c/exchange` (авторизация `checkauth`, `init`, приём файлов).
Включается в `.env`: `EXCHANGE_1C_ENABLED=true`, `EXCHANGE_1C_LOGIN`, `EXCHANGE_1C_PASSWORD`.

Следующий этап — разбор `import.xml` / `offers.xml` и выгрузка заказов (`backend/app/exchange/commerceml.py`).
